委托是否一致

父区委托是递归解析器看到的 NS。子区自报是从一台置了 AA 的权威上用 RD=0 问到的 NS。

怎么一起看

邮件

看 MX，再看 TXT 里的 SPF，以及 _dmarc 这个名字上的 TXT。

证书校验

看 _acme-challenge 上的 TXT。名字里的下划线是合法的。

怀疑应答被换过

看 DS、DNSKEY、RRSIG 是否都在，以及验证型解析器有没有置 AD。记录都在不等于签名有效。

正在换名称服务器

看每台权威的 SOA 序列号是否一致，再看父区委托和子区自报的 NS 是不是同一组。

常见问题

        

        

          怎么查一个名字？
          
输入 example.com，或 _dmarc.example.com 这种带下划线的名字。类型可选 A、AAAA、CNAME、MX、TXT、NS、SOA、CAA、SRV、PTR。ALL 会把常见类型列在一张表里，链路和传播按有答案的那个类型展开。

        

        

          刚改的记录还是旧的，是这里坏了吗？
          
先看传播表里权威那一行。它已经是新值，就是递归器还拿着缓存，等 TTL。它还是旧值，区数据本身还没换。问递归器用 rd=1，问权威用 rd=0。问反了会得到 SERVFAIL，那不是故障。

        

        

          序列号为什么要一致？
          
同一套权威靠序列号判断是不是同一版数据。一台落后，不同解析器就可能拿到不同答案。如果 SOA 的主服务器不是同一台，两套序列号各自计数，那是迁移中的两套权威，不一定是同步坏了。

        

        

          链上的记录都在，就等于签名有效吗？
          
不等于。这里看 DS、DNSKEY、RRSIG 在不在，以及验证型解析器有没有置 AD。不做密码学校验。要判断签名本身，用本机的 dig +dnssec 或带校验的解析器。

        

        

          耗时为什么和我本机的 dig 不一样？
          
数字从这台服务器量到解析器，经常含一次 TCP 握手。拿来横向比较谁先拿到新答案，不代表你家网络的延迟。

        

        

          能从 IP 反查名字吗？
          
能。输入 1.1.1.1 或 2001:db8::1，会转成 in-addr.arpa 或 ip6.arpa 并查 PTR。手写反查名也可以。
